# wayfind

A map of a codebase you do not know, and a ticket resolved to the files it will actually touch.

## What it does

`wayfind` surveys a repo and writes `.forge/map.md`: the areas, the rules about what lives
where, and the exceptions to those rules. Given a ticket, it names the files it expects to
change, before anything is edited.

The constraint that makes it useful is that **every rule it writes carries its basis**: a
census, a document, or the user. A convention asserted from two files is a guess, and it says
so rather than stating it as fact. The exceptions are the part that cannot be regenerated by
looking again, which is why the map is worth keeping.

## When to reach for it

Type `/wayfind`, or the agent reaches for it when a task lands in unfamiliar territory.

Reach for it in a repo you have not worked in, when a ticket arrives with no file names, or
when you suspect a convention exists and want to know whether it actually holds. For a question
about how the whole app fits together rather than where one change goes, use [atlas](atlas.md).

## The map goes stale, loudly

`check` re-runs the map's rules against the current tree. A dead rule is worse than no rule:
it is confidently wrong, and it was right once, so it reads as trustworthy. Run `check` before
trusting a map you did not just build.

## It's working if

- The files it predicted are the files you edited.
- It tells you a convention you believed in does not hold, with the count.
- It records an exception you would otherwise have rediscovered on your third visit.
