# forge

The router. Ask it which of the other seventeen fits what you are about to do.

## What it does

`forge` is a map of the skill set: the main flow most work travels, the on-ramps that feed it,
the ones that belong to no flow, and a table resolving every pair that look like each other.

It exists because a set this size fails in one specific way, and it is not that any skill is
bad. It is that the skill you need is the one you have forgotten you have. The router is the
index you do not have to keep in your head.

## When to reach for it

You type `/forge`; the agent will not reach for it on its own, and should not. A model that
already knows which skill fits does not need to ask, and one that asks is stalling.

Reach for it when you can describe the situation but not name the tool, when two skills sound
like they both apply, or when you have not opened this set in a month.

## The overlap table is the point

The bucket listing is browsable from the directory. What is not recoverable anywhere else is
the disambiguation: `untangle` versus `task` versus `grill` all sound like "there is a problem
and I want help". They differ by what is actually unknown.

| Unknown | Skill |
|---|---|
| The cause | `untangle` |
| Whether the plan holds | `grill` |
| Nothing, it just has to get done | `task` |
| Where the change goes | `wayfind` |
| How the whole app fits together | `atlas` |

That distinction is the difference between an hour and a day, and it is invisible from the
skill names.

## It's working if

- You reach for a skill you had forgotten existed, more than once.
- You stop asking "is there something for this" and start asking `/forge`.
- The answer is sometimes "none of them, just do the work". A router that always routes is
  selling.
